Convert a VCF/BCF to another build

Upload a VCF/BCF plus chain, source FASTA, and destination FASTA assets. DuckGeneSnap will run the Rduckhts bcftools_liftover() row kernel locally and download a lifted variant table. Upload the lifted output to the main annotation workflow when builds match.

Liftover status will appear here.

UCSC chain files are commonly available under hg19 liftOver and hg38 liftOver. Use the same source FASTA used to call the VCF and the matching destination reference. Whole-genome FASTA URLs can be large and may fail if the host blocks CORS.

23andMe text cleanup and VCF conversion

23andMe-style text files carry rsID, chromosome, position, and genotype, but not a guaranteed REF/ALT representation. DuckHTS duckdb_munge is designed for GWAS summary statistics, not personal genotype calls, but the same reference-harmonization idea applies: compare alleles against the selected reference FASTA, detect swaps/reverse complements when unambiguous, and emit called alternate biallelic SNVs as VCF rows.

  • FASTA alone is enough only for unambiguous single-base SNP rows where the chip alleles identify REF vs ALT.
  • A chip manifest or dbSNP/allele map is still needed for strand-ambiguous A/T or C/G SNPs, indels, multi-allelic probes, and vendor-specific probe encodings.
  • The future local converter should output both a VCF/BCF and a QC report: matched reference, swapped/reverse-complemented, ambiguous, no-call, and skipped rows.
Practical rule: use direct chip-text matching only for quick locus checks. For allele-aware interpretation, convert chip data to VCF/BCF with explicit build, reference FASTA, and manifest/dbSNP allele metadata, then upload the converted file to the main annotation workflow.
